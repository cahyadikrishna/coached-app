# AI Coach Assistant

A Rails 8 application that connects to your [Strava](https://www.strava.com)
account, pulls your recent activities, and uses an AI coach (DeepSeek) to
generate concise weekly training summaries with actionable recommendations.

## Features

- **Strava OAuth login** — sign in with your Strava account (`read,activity:read_all` scope).
- **Activity dashboard** — last 7 days of activities with distance, moving time, elevation, and speed stats.
- **Activity details** — per-activity breakdown including heart rate and calories when available.
- **AI coaching summaries** — generate and review weekly summaries written by DeepSeek, including aggregated metrics and trend highlights.
- **Background processing** — summaries are generated asynchronously via Solid Queue.

## Tech stack

- **Ruby** 3.4.10 (see `.ruby-version`)
- **Rails** 8.1
- **Importmap + Hotwire** (Turbo, Stimulus) — no Node build step
- **Tailwind CSS** via `tailwindcss-rails`
- **SQLite** in development/test, **PostgreSQL** (e.g. Supabase) in production
- **Faraday** — Strava API client
- **ruby-openai** — DeepSeek chat API client
- **Solid Queue / Solid Cache / Solid Cable** — jobs, cache, and Action Cable
- **Kamal + Docker** — deployment

## Prerequisites

- Ruby 3.4.10 (use [rbenv](https://github.com/rbenv/rbenv) or similar)
- Bundler
- A [Strava API application](https://developers.strava.com/) (Client ID + Client Secret)
- A [DeepSeek API key](https://platform.deepseek.com/)

## Setup

1. Install dependencies:

   ```bash
   bundle install
   ```

2. Configure environment variables:

   ```bash
   cp .env.example .env
   ```

   Fill in your Strava and DeepSeek credentials (see
   [Environment variables](#environment-variables) below).

3. Prepare the database and start the server:

   ```bash
   bin/setup
   ```

   Or, step by step:

   ```bash
   bin/rails db:prepare
   bin/dev
   ```

4. Open http://localhost:3000 and sign in with Strava.

### Strava API application

1. Create an app at https://www.strava.com/settings/api.
2. Copy the **Client ID** and **Client Secret** into `.env`.
3. Set the **Authorization Callback Domain** to `localhost` and the callback
   path to `/auth/strava/callback`.
4. The app requests the `read` and `activity:read_all` scopes automatically.

### DeepSeek API key

1. Create an account at https://platform.deepseek.com and generate an API key.
2. Put it in `.env` as `DEEPSEEK_API_KEY`.

## Environment variables

| Variable | Required | Description |
| --- | --- | --- |
| `STRAVA_CLIENT_ID` | Yes | Strava application client ID |
| `STRAVA_CLIENT_SECRET` | Yes | Strava application client secret |
| `STRAVA_REDIRECT_URI` | Yes | OAuth callback URL, e.g. `http://localhost:3000/auth/strava/callback` |
| `DEEPSEEK_API_KEY` | Yes | DeepSeek API key |
| `DEEPSEEK_API_BASE` | No | Defaults to `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | No | Defaults to `deepseek-chat` |
| `DATABASE_URL` | Production only | PostgreSQL connection string for the production database (Supabase). Do not set it locally — it would override SQLite in development. |

Never commit `.env` or `config/master.key`. Both are git-ignored.

## Database

- **Development / test**: SQLite, stored in `storage/`.
- **Production**: PostgreSQL configured via `DATABASE_URL` (see
  `config/database.yml`). Solid Queue/Cache/Cable continue to use SQLite files
  under `storage/`.

To reset a local database:

```bash
bin/rails db:reset
```

## Testing & linting

```bash
bin/rails test          # run the test suite
bin/rubocop             # lint (rails-omakase style)
bin/brakeman --no-pager # static security scan
bin/bundler-audit       # gem vulnerability scan
bin/importmap audit     # JS dependency scan
```

The `scan_*`, `lint`, and `test` jobs are also wired into GitHub Actions
(`.github/workflows/ci.yml`).

## Background jobs

Weekly summaries are generated by `GenerateWeeklySummaryJob` (Solid Queue).
In development, jobs run inline via `bin/dev`. In production, the Solid Queue
supervisor runs inside the Puma process (`SOLID_QUEUE_IN_PUMA=true`), or you
can run a dedicated worker with `bin/jobs`.

## Deployment

The app ships with a production `Dockerfile` and a Kamal config
(`config/deploy.yml`).

```bash
bin/kamal setup
bin/kamal deploy
```

Notes:

- `config/deploy.yml` contains placeholder values (server IP, registry, host)
  — update them before deploying.
- Set `RAILS_MASTER_KEY` as a Kamal secret (pulled via `.kamal/secrets`).
- Set `DATABASE_URL` to your Supabase PostgreSQL connection string in the
  production environment.
